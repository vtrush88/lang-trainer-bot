# Daily practice — расписание повторов и новых слов (план)

> **For agentic workers:** short plan, 4 tasks. Execute with superpowers:subagent-driven-development.
> Spec changes go to `docs/superpowers/specs/2026-09-30-daily-practice-design.md` (Task 4 переписывает
> разделы, не только добавляет дельту).

**Статус:** 2026-10-08 — два раунда кросс-модельного ревью (Codex: 3/9/2 и 2/5/2) приняты и внесены
(см. «Провенанс плана»). Ревью остановлено — дальше код и тесты.

## Зачем

За 5 дней после запуска бот каждое утро присылал первое задание для нового слова и ни разу — повтор.
Причина: `pick_due_card` ставит новые карточки (`interval_days = 0`) первыми, а у Victoria 13 слов
добавлены до запуска и все «новые»; 10 карточек с просроченным повтором ждут за ними. Лесенка 1→3→7→14
не работает, если повтор не приходит в свой день.

**Решение Victoria (2026-10-08):** лесенка не ломается никогда; новые слова — не больше двух в неделю и
равномерно; `/next` повторы не выдаёт (они приходят сами); кнопка «Ещё одно» не нужна; долг
просроченных повторов разобрать за два дня.

## Поведение (контракт)

**Бизнес-дата.** Везде «сегодня» = календарная дата в `DAILY_TZ` через новый общий модуль
`clock.py` (`clock.configure(tz_name)`, `clock.today() -> date`), не серверный `date.today()`. Это
касается и общих хендлеров `handlers/add.py` (`created_at`) и `handlers/training.py` (`due_at`,
выборка due) — иначе слово, сохранённое около полуночи, станет доступным не в тот день, а тренировка
запишет не ту дату. Для маминого бота зона та же (`DAILY_TZ` по умолчанию Europe/Madrid, мама в
Мадриде), тексты ES не меняются. Цепочка после ответа берёт дату **заново под локом** перед
`_issue_locked` (ответ, начатый до полуночи, не должен выдать следующее задание вчерашним днём).

**Повторы (карточки с `interval_days > 0` и `due_at <= today`).**
- Утром приходит самый просроченный (`ORDER BY due_at, id`).
- После **успешно отправленного** результата ответа (верно / неверно / «не помню» / «фраза удалена»)
  бот сам присылает следующий повтор на сегодня, пока они есть — без кнопки. Цепочка не идёт после
  «попробуй ещё» (ответ-копия подсказки — задача ещё открыта) и после сбоя отправки результата
  (иначе ученик увидит следующее задание без разбора предыдущего); для этого и `_send_result`, и
  `_safe_send` (ветка «фраза удалена» через `_close_deleted`) возвращают `bool`.
- Сбой выдачи следующего задания в цепочке (Telegram) — принятая деградация: лог, без текста
  (если Telegram не отдаёт, текст тоже не дойдёт); повтор придёт следующим утром. Gemini в цепочке не
  бросает: `prepare_task` деградирует до примера/без предложения.
- Не больше `MAX_REPEATS_PER_DAY = 5` повторов в календарный день. Что не влезло — следующим утром,
  самый просроченный первым. Долг разбирается в темпе ответов: утро даёт только первое задание,
  остальные приходят по цепочке после каждого ответа.

**Новые слова (`interval_days = 0`, `created_at < today`).**
- Норма: не больше `NEW_PER_WEEK = 2` за ISO-неделю (пн–вс) и не чаще, чем раз в `NEW_MIN_GAP_DAYS = 3`
  дня (получается ~пн/чт без привязки к дням). Не больше одного нового в день.
- Норма считается **по таблице задач**, не по отдельному счётчику: `is_new = 1` у задач, выданных по
  карточке с `interval_days = 0`; «за неделю» = **число различных карточек** (`COUNT(DISTINCT card_id)`)
  с `is_new = 1` и `sent_on` от понедельника текущей ISO-недели до сегодня — повторная выдача той же
  неотвеченной карточки (истекла утром) второй слот не съедает; «последнее новое» = `MAX(sent_on)`
  среди `is_new = 1`. Выкат посреди недели корректен за счёт backfill'а (см. «Данные»).
- Новое слово приходит само **только когда повторов на сегодня больше нет** (`pick_due_repeat` пуст):
  утром, если повторов нет, либо после последнего повтора дня. Если упёрлись в `MAX_REPEATS_PER_DAY`,
  а повторы ещё есть — нового слова в этот день нет (долг важнее).
- Порядок новых: сначала карточки, по которым **ещё не было ни одной задачи** (`NOT EXISTS` в
  `daily_tasks`), самые свежие первыми (`ORDER BY id DESC`); потом уже показанные, но не отвеченные
  (истёкшие) — тоже свежие первыми. Свежий контекст из жизни важнее старого «склада» (13 слов до
  запуска дойдут постепенно). *(Решение автора плана; флаг Victoria.)*
- `/next` даёт новое слово в рамках той же нормы. Результаты и тексты:
  - норма исчерпана → `TEXT_NEXT_LATER` «Новое слово будет {when} 🙂» (`when`: «завтра» / «через N
    дня/дней»);
  - новых карточек нет, но есть сохранённые сегодня (`created_at = today`) → `TEXT_NEXT_TOMORROW`
    «Сохранённое сегодня придёт завтра 🙂»;
  - новых карточек нет вообще → `TEXT_NO_NEW_WORDS` «Новых слов нет — перешли что-нибудь 🙂»;
  - есть открытое задание → повторить его («resent»), ничего не истекает, `issued_at` обновляется
    (иначе сразу после явного `/next` ответ попадёт в 15-минутный «переспрос»); если у открытой задачи
    карточка уже удалена — как сейчас: задача истекает, поиск продолжается (тест);
  - ошибка отправки → `TEXT_NEXT_FAILED` «Не получилось выдать задание сейчас 😕 Попробуй /next через
    минутку.» (не `TEXT_CAPTURE_FAILED` про «другое слово»).

**Что остаётся как было:** тихий режим (3 пропущенных утра → раз в 7 дней); истечение неотвеченной
утренней задачи следующим утром (+ пропуск, если утренняя); 15-минутный текстовый режим
«переспросить» для задач `/next`; виды заданий по ступеням; тексты заданий и разборов.

**Что убирается:** `MAX_TASKS_PER_DAY`, `more_button_allowed`, `keyboards.more_keyboard`, хендлер
`on_more`, `TEXT_MORE_*`, `TEXT_NOTHING_NEXT`, параметр `limit` и результат `"limit"` у
`send_daily_task`; истечение stale-задачи по `/next` (дельта (р), вторая половина) — теперь `/next`
только повторяет открытую задачу.

## Данные

- `daily_tasks.is_new INTEGER NOT NULL DEFAULT 0` — 1, если задача выдана по карточке с
  `interval_days = 0` (первое задание слова). Миграция через `_add_missing_columns`.
- **Backfill при каждом старте (идемпотентно, в `init_db` после `_add_missing_columns`):**
  `UPDATE daily_tasks SET is_new = 1 WHERE kind = 'compose_hinted' AND is_new = 0` — `compose_hinted`
  выдаётся только на нулевой ступени, поэтому признак точный; выполнение на каждом старте закрывает
  сценарий «ALTER прошёл, процесс упал до UPDATE». Без backfill'а норма «2 в неделю» на текущих
  данных сразу нарушится (на этой неделе уже выдано 4 новых слова).
- Никаких новых колонок в `daily_state`: недельная норма выводится из `daily_tasks`.
- ES-бот: таблица `daily_tasks` пустая, миграция — колонка с дефолтом, backfill ничего не трогает.

## Задачи

### Task 1 — `db.py` + `clock.py`: колонка, backfill, выборки, бизнес-дата
- Новый модуль `clock.py`: `configure(tz_name: str | None)` (None → локальная зона), `today() -> date`,
  `now() -> datetime` (aware). `daily._utcnow` остаётся для `issued_at`.
- `_add_missing_columns`: `daily_tasks.is_new`; `init_db` после него выполняет backfill
  (`UPDATE … WHERE kind = 'compose_hinted' AND is_new = 0`) при каждом старте.
- `pick_due_repeat(conn, user_id, today)` — `interval_days > 0 AND due_at <= today AND enriched = 1
  AND translation IS NOT NULL AND translation != ''`, `ORDER BY due_at, id LIMIT 1`.
- `pick_new_card(conn, user_id, today)` — `interval_days = 0 AND enriched = 1 AND translation …
  AND created_at < today`, `ORDER BY (EXISTS(SELECT 1 FROM daily_tasks t WHERE t.card_id = cards.id)),
  id DESC LIMIT 1` (никогда не показанные первыми, затем показанные-неотвеченные; свежие первыми).
- `has_new_cards_created_on(conn, user_id, today) -> bool` — `interval_days = 0 AND created_at = today`
  (для `TEXT_NEXT_TOMORROW`).
- `pick_due_card` — удалить (единственный вызов уходит вместе с `more_button_allowed`).
- `count_repeats_on(conn, user_id, today)` — `sent_on = today AND is_new = 0`;
  `count_new_on(conn, user_id, today)` — `sent_on = today AND is_new = 1`.
- `count_new_since(conn, user_id, since: date, today: date)` — `COUNT(DISTINCT card_id) WHERE is_new = 1
  AND sent_on BETWEEN since AND today`; `last_new_on(conn, user_id) -> date | None` — `MAX(sent_on)
  WHERE is_new = 1`.
- `create_task(..., is_new: bool = False)` — одна запись (норма выводится из неё, отдельного
  «учёта» нет → нет окна между двумя коммитами).
- `touch_task_issued_at(conn, task_id, now)` — обновить `issued_at` при повторе по `/next`.
- Тесты (`tests/test_db_daily.py`, новый `tests/test_clock.py`): миграция идемпотентна; backfill
  помечает только `compose_hinted` и срабатывает при повторном `init_db` на базе, где колонка уже
  есть, а `is_new = 0` (прерванная миграция); на legacy-базе (задачи этой недели без `is_new`) после
  миграции `count_new_since` считает их; `count_new_since` считает одну карточку один раз при двух
  задачах; порядок `pick_due_repeat` (самый просроченный, tie по id) и `pick_new_card` (не показанные
  раньше показанных, свежие первыми, `created_at < today`); счётчики; `last_new_on`; `clock.today()`
  в заданной зоне (23:30 UTC = завтра в Madrid) и без конфигурации.

### Task 2 — `daily.py`: чистая логика, дата, тексты
- Константы `MAX_REPEATS_PER_DAY = 5`, `NEW_PER_WEEK = 2`, `NEW_MIN_GAP_DAYS = 3`; удалить
  `MAX_TASKS_PER_DAY`. Модульный `rng = random.Random()` (дефолт для выдачи; хендлеры свой `_rng`
  убирают).
- Бизнес-дата: `daily_loop` и всё в `daily.py` берут `clock.today()` (модуль из Task 1).
- `week_start(today) -> date` — понедельник ISO-недели.
- `new_word_allowed(*, count_this_week: int, last_new: date | None, today: date) -> bool` —
  `count_this_week < NEW_PER_WEEK` **и** (`last_new is None` или `(today - last_new).days >=
  NEW_MIN_GAP_DAYS`).
- `days_until_new_word(*, count_this_week, last_new, today) -> int` — `max(gap_wait, week_wait)`:
  `gap_wait = NEW_MIN_GAP_DAYS - (today - last_new).days` (≥ 0, 0 если `last_new` пусто);
  `week_wait` = дней до следующего понедельника, если `count_this_week >= NEW_PER_WEEK`, иначе 0.
  Если результат 0 при исчерпанной норме — не бывает по построению (тест).
- `when_text(days: int) -> str` — «завтра» при 1, иначе «через N дня» (2–4) / «через N дней».
- Тексты: `TEXT_NEXT_LATER`, `TEXT_NEXT_TOMORROW`, `TEXT_NO_NEW_WORDS`, `TEXT_NEXT_FAILED` (значения
  выше); `TEXT_SAVED = "Сохранено ✅ — придёт с ближайшим новым словом."`. Удалить
  `TEXT_MORE_STALE/LIMIT/EMPTY`, `TEXT_NOTHING_NEXT`.
- Тесты (`tests/test_daily.py`): `week_start`, `new_word_allowed` (2 в неделю, 3 дня, граница недели),
  `days_until_new_word` (гап, неделя, оба), `when_text` склонение.

### Task 3 — выдача, цепочка, `/next`, уборка кнопки
- `daily.py`:
  - `_issue_locked(bot, conn, llm, profile, user_id, today, rng, *, morning, want_new, chain) -> str`
    — вызывается **уже под** `user_lock`. `send_daily_task(bot, conn, llm, profile, user_id, today,
    rng=None, *, morning=False, want_new=False) -> str` берёт лок и зовёт её (`rng or daily.rng`).
    Результаты: `"sent" | "resent" | "nothing" | "later" | "tomorrow" | "failed"`.
  - Выбор в `_issue_locked`:
    1. открытая задача: утро — как сейчас (сегодняшняя → `"nothing"`, вчерашняя → истечь (+ bump,
       если утренняя) и продолжить выдачу); `/next` (`want_new`) — повторить (`"resent"`) +
       `touch_task_issued_at`; цепочка (`chain=True`) → `"nothing"` (страховка — задача только что
       закрыта под этим же локом);
    2. утро: `should_send` (тихий режим) → `"nothing"`;
    3. если не `want_new`: `repeat = pick_due_repeat(...)`; если он есть и
       `count_repeats_on < MAX_REPEATS_PER_DAY` → выдать его; если он есть, но лимит исчерпан →
       `"nothing"` (нового слова в день долга нет);
    4. иначе (повторов нет или `want_new`): `count_new_on(today) == 0` и
       `new_word_allowed(count_new_since(week_start..today), last_new_on, today)` → `pick_new_card`;
       при `want_new`: норма исчерпана → `"later"`; карточек нет, но `has_new_cards_created_on(today)`
       → `"tomorrow"`; нет вовсе → `"nothing"`;
    5. нечего → `"nothing"`.
    `/next` при открытой задаче с удалённой карточкой — как сейчас: истечь и продолжить поиск.
    При новой карточке — `create_task(is_new=True)`. `set_last_sent` — только утром.
  - `answer_task(..., rng=None)`: `_send_result` и `_safe_send` возвращают `bool` (успех отправки);
    на всех ветках `"done"` (обычный ответ, «не помню», удалённая карточка через `_close_deleted`)
    после успешной отправки — **внутри того же лока**, с датой `clock.today()`, взятой заново,
    `await _issue_locked(..., morning=False, want_new=False, chain=True)`; `"failed"` из цепочки и
    любое исключение — `log.warning`, результат ответа не меняется. Без кнопки у результата.
  - Удалить `more_button_allowed`.
- `handlers/daily.py`, `handlers/add.py`, `handlers/training.py`: все `date.today()` →
  `clock.today()` (ES-тексты и логика не меняются — только источник даты); `cmd_next` →
  `send_daily_task(..., want_new=True)`; `"later"` → хендлер читает `db.count_new_since` /
  `db.last_new_on` и `days_until_new_word` → `TEXT_NEXT_LATER.format(when=…)` *(чтение вне лока —
  принятая гонка: максимум ошибка в днях на границе суток)*; `"tomorrow"` → `TEXT_NEXT_TOMORROW`;
  `"nothing"` → `TEXT_NO_NEW_WORDS`; `"failed"` → `TEXT_NEXT_FAILED`. Удалить `on_more` и `_rng`;
  из `daily_button_inside_mode` убрать `"more:"`.
- `keyboards.py`: удалить `more_keyboard`. `handlers/commands.py`: описание `/next` — «новое слово».
- `bot.py`: `clock.configure(cfg.daily_tz)` до старта (для обоих ботов); `run_morning` — без
  изменений интерфейса.
- Тесты. `tests/test_daily_send.py`: утро — повтор раньше нового; повторов нет и норма есть → новое
  (`is_new = 1`); норма исчерпана → `"nothing"` утром; 6 повторов due → 5 за день, шестой завтра;
  (с доступной новой карточкой: после пятого повтора новое слово НЕ приходит); вчерашняя открытая
  утренняя → истекла + bump + выдан повтор в том же вызове; `/next` при норме → новое; норма
  исчерпана → `"later"`; карточка сохранена сегодня → `"tomorrow"`; `/next` при открытой задаче →
  `"resent"`, задача не истекла, `issued_at` обновлён; `/next` при открытой задаче с удалённой
  карточкой → истекла, поиск продолжен; stale-текст после `/next`-повтора не переспрашивает;
  повторно выданная неотвеченная новая карточка не съедает второй слот недели. `tests/test_daily_answer.py`: после ответа приходит следующий повтор (fake bot
  получил второе задание, `is_new = 0`); после последнего повтора — новое слово, если норма позволяет,
  иначе ничего; цепочка после «не помню» и после «фраза удалена»; после `"retry"` цепочки нет;
  сбой отправки результата (и сбой `_safe_send` для «фраза удалена») → цепочки нет; сбой `deliver`
  в цепочке (`"failed"`) → результат ответа `"done"`, в логе warning, задача не создана; цепочка
  берёт дату заново (monkeypatch `clock.today` меняется между ответом и цепочкой → `sent_on`
  новой задачи = новая дата); гонка `answer_task` и утреннего `send_daily_task` на реальном
  `user_lock` — утро ждёт и не истекает задачу, цепочка и утро не выдают две задачи.
  `tests/test_daily_capture.py`: тексты `/next`; `tests/test_keyboards.py`, `tests/test_bot_wiring.py`:
  упоминания `more` убрать, `clock.configure` вызван в `main` для обоих профилей;
  `tests/test_handlers*.py`/training: `clock.today` подменяется там, где раньше `date.today`.
  ES-регрессия: существующие
  `test_build_dispatcher_excludes_daily_router_for_es` и `menu_markup`-тесты остаются зелёными.

## Глобальные ограничения
- ES-профиль байт-в-байт; `languages.py` не трогать. Новые колонки — с дефолтами. ES dispatcher не
  подключает daily-роутер и цикл (`tests/test_bot_wiring.py`), reply-меню прежнее
